Everything built across both labs lives in two databases, one warehouse and — if you completed the sharing optional in Lab 1 — one share. This removes all of it.

⚠️
This is irreversible beyond the Time Travel window

Dropping a database starts its Time Travel clock, and UNDROP DATABASE works only until the retention period expires. Past that point the objects, the 2.4 million ledger lines, the rule tables and every view over them are gone with no recovery path. Run this only when you have finished with the environment. If you want to keep the work and stop the compute cost, run ALTER WAREHOUSE GSI_TAX_WH SUSPEND; instead and leave the databases in place — a suspended warehouse consumes no credits, and under a gigabyte of storage costs cents a month.

sql
-- Drop the share FIRST. A share cannot be dropped implicitly with the database
-- it grants on, and while it exists the database cannot be dropped at all:
-- "cannot be dropped. It is still shared by 1 shares". This is the share
-- Lab 1 Step 8 creates.
DROP SHARE IF EXISTS GST_AUDIT_SNAPSHOT_SHARE;

-- The scenario clone from Lab 1 Step 7. Harmless if it was already dropped
-- at the end of that step, or never created.
DROP DATABASE IF EXISTS GSI_TAX_SCENARIO;

-- The workshop itself: all seven schemas, both Dynamic Tables, every view,
-- the rule tables and the Streamlit app object.
DROP DATABASE IF EXISTS GSI_TAX_WORKSHOP;

-- The warehouse last, so the statements above have compute to run on.
DROP WAREHOUSE IF EXISTS GSI_TAX_WH;

-- Confirm. Both queries should return zero rows.
SHOW DATABASES LIKE 'GSI_TAX%';
SHOW WAREHOUSES LIKE 'GSI_TAX%';

Every statement uses IF EXISTS, so the block runs clean whether or not you completed the optional steps. Dropping GSI_TAX_WORKSHOP takes the Streamlit app with it, because the app object lives in the APPS schema.

💡
The agent and the semantic views need removing separately

GST_COMPLIANCE_AGENT was created through Snowsight and is not an object inside GSI_TAX_WORKSHOP, so dropping the database does not remove it. Open AI & ML → Agents, select the agent and delete it there. Do the same for any semantic view you created through AI & ML → Cortex Analyst — SV_GST_COMPLIANCE, and SV_SUPPLIER_RISK if you built the second tool. An agent left pointing at a dropped semantic view will not cost anything, but it will fail confusingly for the next person who finds it.
