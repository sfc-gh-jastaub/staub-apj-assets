One query, all four layers

The query below counts every object the lab depends on and puts the expected count beside the actual one, so you diagnose your own environment rather than checking numbers against someone else's screen.

sql
USE DATABASE GSI_TAX_WORKSHOP;
USE WAREHOUSE GSI_TAX_WH;

SELECT 1 AS SORT_KEY, 'RAW'      AS LAYER, 'RAW_DATA.ERP_SAP_GL'     AS OBJECT_NAME,
       COUNT(*) AS ACTUAL_ROWS, 1200000 AS EXPECTED_ROWS,
       IFF(COUNT(*) = 1200000, 'OK', 'CHECK') AS STATUS
FROM RAW_DATA.ERP_SAP_GL
UNION ALL
SELECT 2, 'RAW',     'RAW_DATA.ERP_ORACLE_GL',  COUNT(*),  800000,
       IFF(COUNT(*) =  800000, 'OK', 'CHECK') FROM RAW_DATA.ERP_ORACLE_GL
UNION ALL
SELECT 3, 'RAW',     'RAW_DATA.ERP_LEGACY_AP',  COUNT(*),  400000,
       IFF(COUNT(*) =  400000, 'OK', 'CHECK') FROM RAW_DATA.ERP_LEGACY_AP
UNION ALL
SELECT 4, 'RAW',     'RAW_DATA.DOC_TAX_INVOICE', COUNT(*),     300,
       IFF(COUNT(*) =     300, 'OK', 'CHECK') FROM RAW_DATA.DOC_TAX_INVOICE
UNION ALL
SELECT 5, 'CURATED', 'CURATED.GL_HARMONISED',   COUNT(*), 2400000,
       IFF(COUNT(*) = 2400000, 'OK', 'CHECK') FROM CURATED.GL_HARMONISED
UNION ALL
SELECT 6, 'TAX',     'TAX.V_GST_DETERMINED',    COUNT(*), 2400000,
       IFF(COUNT(*) = 2400000, 'OK', 'CHECK') FROM TAX.V_GST_DETERMINED
UNION ALL
SELECT 7, 'TAX',     'TAX.V_GST_VS_BAS',        COUNT(*),     532,
       IFF(COUNT(*) =     532, 'OK', 'CHECK') FROM TAX.V_GST_VS_BAS
UNION ALL
SELECT 8, 'TAX',     'TAX.V_GST_EXCEPTIONS',    COUNT(*),  258145,
       IFF(COUNT(*) =  258145, 'OK', 'CHECK') FROM TAX.V_GST_EXCEPTIONS
ORDER BY SORT_KEY;

🔧
If any count is zero

A zero means the object exists but was never populated, or the schema was created and the load never ran. Re-run gsi_tax_lab0_setup.ipynb in full and then re-run this query. If a statement fails with an object-not-found error instead of returning zero, the object was never created at all and Lab 1 needs to be worked through from the beginning. Do not proceed into the AI steps with a partial foundation — the failures will look like AI problems and they will not be.

The 300-row table is the one to notice. It is the only object in the account holding free text, it has been sitting there since setup completely unused, and it is where the next four steps happen. Everything a human wrote about these transactions is in there, and so far nothing in your pipeline has been able to do anything with it.
